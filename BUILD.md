# Build & deploy

The course is a static single-page app — no build step is required to run it.
Open `index.html`, or serve the folder (`npm run serve`) and visit it.

There is **one optional build step for SEO**: prerendering crawlable pages and
social-share images. You only need to re-run it when lesson content changes.

## The SEO build

```
npm run build          # = node tools/build_seo.js
```

This regenerates, from `curriculum.js` + `content/track*.js`:

- `lessons/<id>.html` — one crawlable static page per lesson, with the lesson's
  text, `<title>`, meta description, canonical URL, Open Graph + Twitter tags,
  and JSON-LD (LearningResource + BreadcrumbList). Search engines and social
  unfurlers read these; humans are redirected into the app.
- `sitemap.xml` and `robots.txt`.
- `og/<track>.png` + `og/og-default.png` — 1200×630 social-share images
  (generated by `tools/build_og.py`, which needs **Pillow** and **numpy**:
  `pip install pillow numpy`). If those aren't installed the pages still build;
  only the images are skipped.

The site's base URL is set once at the top of `tools/build_seo.js`
(`const BASE = ...`). Change it if you fork or rehost.

## Deploying to GitHub Pages

Pages serves the repo as-is (no server build), so the generated files are
committed and pushed like everything else:

```
npm run build
git add -A
git commit -m "Rebuild SEO pages"
git push
```

Pages redeploys in a minute or two. After the first deploy, submit
`https://<you>.github.io/<repo>/sitemap.xml` to Google Search Console so the
per-lesson pages get indexed.

> Note: on a GitHub Pages *project* site the effective `robots.txt` is the one at
> the domain root (`<you>.github.io/robots.txt`), which you don't control — so
> rely on the sitemap + Search Console for indexing rather than the project
> `robots.txt`.

## Everything else

- `npm run verify` — run the lesson integrity checker over every track.
- `npm run serve` — serve locally at `http://localhost:8080`.
