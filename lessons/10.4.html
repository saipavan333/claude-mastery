10.4 · Managed Agents: Agents Without Servers

Managed Agents: production agents without servers — Anthropic-hosted, with built-in memory, scheduling, webhooks, and streaming. The no-infrastructure path to deployed agents.

In one breath: Managed Agents run your agents on Anthropic's infrastructure — you define the agent once (model, prompt, tools, MCP, skills), then start sessions via API — with built-in memory stores, scheduled runs, webhooks, and session overrides, so you get production agents without running any servers.

What Managed Agents is

Anthropic-hosted agent runtime: you define an agent (model, system prompt, tools, MCP servers, skills) ONCE, then start SESSIONS against it via API — Anthropic runs the loop in a managed sandbox. No servers, no scaling, no ops (as of July 2026, public beta — verify current status/features in docs). Built-in capabilities you'd otherwise build: Memory stores — persistent agent memory with search/update, so your agent remembers across sessions (9.2's statelessness, solved as a managed feature — the extract/store/retrieve architecture, hosted). Scheduled deployments — run agent sessions on a cron schedule (5.5's scheduled tasks, for your custom agents). Webhooks — lifecycle events pushed to you (no polling) — react when an agent finishes, a session changes, etc. Session overrides & event streaming — customise per-session (model, prompt, tools), and stream agent messages incrementally (9.2's streaming, for agents). The sandbox includes tools: file operations, bash, web search/fetch, MCP servers, in Anthropic's isolated environment — the 7.4 full-auto habitat (isolation makes autonomy safe), managed for you.

SDK vs Managed: the real decision

Dimension Agent SDK (10.3) Managed Agents Hosting You run the infrastructure Anthropic runs it Control Total — your servers, your rules High, within the managed model Ops burden Yours (scaling, uptime, patching) Anthropic's Memory/scheduling/webhooks You build them Built in Best for Deep control, existing infra, on-prem Speed to production, solo/lean teams, no-infra The honest decision: if you have infrastructure and need deep control (enterprise, on-prem, custom deployment) → SDK. If you want production agents fast without running servers → Managed. Many builders START with Managed (fastest to validate the idea — 12.1's lean principle) and move to SDK only if control needs demand it. There's no wrong choice — just fit. Caveat worth knowing (July 2026): Managed Agents may not yet support every compliance option (e.g., certain data-retention arrangements) — for regulated data, verify current capabilities. The feature set is expanding rapidly; the release notes are truth.

What doesn't change (the judgment is still yours)

The design is entirely yours: Managed Agents runs YOUR agent — your prompts, your tools, your architecture (10.2). Hosting is handled; JUDGMENT is not. A badly-designed agent runs badly on great infrastructure. Security is still yours to design (8.5): the sandbox provides isolation (blast-radius layer), but YOU design the tools (least privilege), break the trifecta, set the hinges. Managed hosting doesn't manage your security architecture. Cost engineering still applies (9.7): managed agents consume API usage (plus any hosting cost) — model mix, caching, loop limits still govern whether the product is profitable. Verification is still non-negotiable (3.4): an autonomous agent, hosted or not, needs the evaluator-optimizer loops, honest failure, and monitoring that make agentic output trustworthy. The infrastructure runs the loop; it doesn't verify the loop's correctness — that's your engineering.

Recap

Managed Agents runs your agents on Anthropic's infrastructure with built-in memory, scheduling, and webhooks — the no-servers path to production, collapsing the infrastructure barrier so your architecture, security, verification, and cost judgment become the whole product.
