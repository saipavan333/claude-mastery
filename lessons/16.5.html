16.5 · Build-Along: The Document-Intelligence Agent (Files API)

Build-Along #B — the document-intelligence agent: use the Files API to upload once and reference by id, then turn floods of PDFs and images into clean, verified data at scale — the highest-volume money in applied AI.

In one breath: The Files API lets you upload a document once, get a file_id, and reference it across many Messages requests instead of re-sending the bytes — and combined with Claude's native PDF and image understanding it becomes the backbone of a document-intelligence agent that ingests invoices, contracts, claims, and forms and returns structured, reconciled data, which is one of the largest and most durable revenue pools in applied AI.

The Files API: upload once, use many times

Instead of embedding a big PDF's bytes in every request, you upload it once and reference a lightweight file_id : files_flow.py — upload then reference from anthropic import Anthropic client = Anthropic() # 1) Upload once -> get a file_id (Files API is GA; no beta header needed) uploaded = client.files.upload( file=("invoice.pdf", open("invoice.pdf", "rb"), "application/pdf"), ) fid = uploaded.id # 2) Reference it by id in a Messages request (document block, source type 'file') resp = client.messages.create( model="claude-sonnet-5-5", max_tokens=800, messages=[{ "role": "user", "content": [ {"type": "text", "text": "Extract vendor, date, currency, subtotal, tax, total, and line items as STRICT JSON. Any field not readable = null. Never guess a number."}, {"type": "document", "source": {"type": "file", "file_id": fid}}, ], }], ) print(resp.content[0].text) copy Endpoints: upload ( POST /v1/files ), list, get metadata, download, delete — a small, clean CRUD surface. Limits: up to 500 MB per file; PDFs, plain text, and images (JPEG/PNG/GIF/WebP); a 1 TB org storage pool. Operations are free — you're billed only for content actually used in a request (as input tokens). Reuse is the win: a document you'll query repeatedly (a 200-page contract) uploads once and is referenced by id thereafter — less bandwidth, and it pairs with prompt caching (9.6) to cut real cost hard.

The pipeline shape (and the model mix)

A document-intelligence agent is the 9.3 discipline wired into a loop: ingest → extract → verify → route . Upload each document, extract to a strict JSON contract (3.3), then — the non-negotiable part — verify by construction , because you cannot eyeball 40,000 extractions (5.3): reconcile totals against a control figure, sample N random extractions against their sources, and flag low-confidence or UNREADABLE fields to a human queue. Mix models for economics (1.3/9.7): Haiku 5.5 for high-volume simple extraction, Sonnet 5.5 for nuanced documents, escalating to Opus 5.5 only for the genuinely hard ones. And keep the professor/calculator law (4.4): Claude reads each number; your code does the arithmetic — never ask the model to total 40,000 invoices in its head.

Security and the honest limits

Two disciplines make this sellable rather than risky. Security (8.5): documents are untrusted input — a PDF can carry a prompt-injection payload — so the extractor treats document content as data, never as instructions, and never follows commands found inside a file. Files are also workspace-scoped (any key in the workspace can reference an uploaded file), so treat file_ids as sensitive server-side references and never accept one from an untrusted source. Honest limits (12.6): extraction quality varies with document messiness; the value you sell is not «100% accuracy» (nobody can promise that on real-world scans) but trustworthy at scale — reconciled totals, sampled checks, and a clean human-review lane for the doubtful, so error rates are known and bounded rather than hidden. That combination — volume plus verifiability — is exactly what a business pays for, and exactly what a weekend-hack competitor skips.

Recap

The Files API (out of beta) is upload-once/use-many: send a document to get a file_id, then reference it by id across requests via a document (or image) block — up to 500 MB per file, operations free, billed only for content used. Built into the ingest→extract→verify→route pipeline, with a Haiku/Sonnet/Opus model mix, strict-JSON contracts, code-side reconciliation, sampling, and a human-review lane, it becomes a document-intelligence agent. Treat document content as untrusted data (8.5), keep arithmetic in code (4.4), and sell 'trustworthy at scale with a known error rate' — not impossible perfection (12.6). Document processing is perennial, high-volume, applied-AI money.
