9.1 · From App to API: Your First Request

The API is the raw brain, programmable — where you stop USING Claude and start BUILDING things that use Claude for other people. Your first real request, demystified.

In one breath: The Claude API takes your messages plus an API key and returns Claude's response as data your code controls — the same brain as the app, with no interface, priced per token, and it's the engine under every product in the money tracks.

The mental model: brain-as-a-function

Strip away the chat window and Claude is a function: messages in → response out . The API is how your code calls that function. Three moving parts: The endpoint — a web address you send a request to (the Messages API). Your code POSTs there; Claude's servers do the thinking; a response comes back. The API key — your credential and your meter. It authenticates you and bills you (per token — 1.3's prices). Get it from the Anthropic Console; treat it like a password (7.8's secrets law is now non-negotiable — a leaked key is someone spending YOUR money). The request/response — you send: which model, the messages, settings (max length, temperature…). You get back: the generated text, plus metadata (tokens used, why it stopped). Structured data your program reads, not prose you read. Everything else in this track is elaboration on that loop. Master the loop and the rest is vocabulary.

Your first request (you don't need to be a programmer)

Here's a complete Python request — and notice you can read it even if you don't «code», because you've been writing its parts for eight tracks: first_call.py — a complete API request import anthropic client = anthropic.Anthropic() # reads ANTHROPIC_API_KEY from environment response = client.messages.create( model="claude-sonnet-5", # the workhorse (1.3) max_tokens=400, # output length cap system="You are a concise travel assistant. Facts only; flag uncertainty.", # 2.6! messages=[ {"role": "user", "content": "Three underrated day-trips from Pune, one line each."} ], ) print(response.content[0].text) copy Read it with your trained eyes: model is 1.3's selection; system is 2.6's casting; messages is the conversation; max_tokens is 2.4's length control. The API isn't new concepts — it's the concepts you own, expressed as code. The SDK (that anthropic library) handles the web plumbing; you handle the intent — same division as every surface.

How to actually learn this (the Claude-Code way)

Build it WITH Claude Code (Track 7): «set up a Python project that calls the Claude API to do X» — it scaffolds, handles the key safely (.env, gitignored — 7.8), writes the call, runs it. You learn by commissioning and reading, exactly as 7.1 promised. The Console is your dashboard: get keys, watch spend, set spending limits (do this FIRST — 1.5's guardrails), and use the Workbench-style tooling to test prompts before coding them. Free-tier reality: the API is pay-per-token from the start (no free chatting allowance), but experiments cost pennies — a few hundred test calls on Haiku is a rounding error. Set a $5 limit and explore fearlessly. The bridge from here: once messages-in-response-out is muscle memory, the rest of this track adds senses (vision), hands (tools), guarantees (structured outputs), and economics (caching, batching) — each a well-defined upgrade to the same loop.

Recap

The API is Claude as a function your code calls — messages in, response out, priced per token — expressing the very skills you already own (model choice, system prompts, format control) as code; set the spending limit and secure the key first, then build.
