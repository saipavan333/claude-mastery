10.5 · Reliability: Evals, Guardrails, Human-in-the-Loop

Reliability engineering: the evaluations, guardrails, and human-in-the-loop design that turn an agent from an impressive demo into a system you can actually deploy and depend on.

In one breath: Agents earn deployment through reliability engineering — evals that measure real performance, guardrails that constrain behaviour deterministically, verification loops that catch errors, and human-in-the-loop design that places people exactly where judgment is irreplaceable — because autonomy without reliability is just automated risk.

Evals: you can't deploy what you can't measure

Agent evals extend 3.6 to full systems: a fixed set of realistic tasks (including messy and edge cases), with success criteria, run against your agent to produce a NUMBER — «passes 47/50 tasks» — that you track as you iterate. What's different for agents: you evaluate not just final output but the PATH — did it use the right tools? did it recover from errors? did it stay within cost/loop bounds? did it handle the exception correctly? Trajectory matters, not just destination. The deployment gate: an agent ships when its eval score on realistic tasks (including the hard ones) meets a bar you set. «Works on the happy path» is not a bar; «handles 95% of real cases correctly and fails safely on the rest» is. Evals catch regressions (3.6): every prompt tweak, model change, or tool update is re-evaluated — because agents are complex systems where a change can silently break a case that used to work. The eval suite is your safety net for change.

Guardrails: deterministic limits on probabilistic behaviour

The two-material engineering (7.5) is load-bearing for agents: Hard limits (deterministic, non-negotiable): loop caps (max iterations — an agent can't spin forever), cost budgets (stop at ₹X — 9.7), timeouts, and action allowlists (the agent can ONLY use these tools, touch these resources — 8.2's least privilege). These are CODE, not instructions — enforced with probability 1 (7.5's instructed-vs-enforced). Validation gates: the agent's outputs pass through deterministic checks before they count — structured-output schemas (9.5), reconciliation (5.3), business-rule validation. The model proposes; the guardrail disposes. The evaluator-optimizer loop (10.2, 3.4) as a reliability pattern: a critic checks the agent's work against criteria and forces revision until it passes — quality assurance built into the loop, catching the errors that autonomy compounds. Fail safe, not silent: when the agent hits a limit, can't complete, or produces something that fails validation, it must FAIL LOUDLY — flag it, stop, route to a human — never fabricate or silently proceed (3.4's honest-failure, agent edition; 5.5's stale-data rule).

Human-in-the-loop: people where judgment is irreplaceable

The design question: not «human or autonomous?» but «WHERE does a human belong?» — and the answer is: at the points of highest consequence and lowest reversibility (5.2's law, agent edition), and where the agent's confidence is low. The patterns: approval gates (human OKs consequential actions before they execute — Claude Code's ask-first, 7.4), exception routing (the agent handles the 95%, escalates the ambiguous 5% to a human — 10.1's invoice design), and review queues (the agent drafts, a human dispatches — 5.5, 4.7's hinge). Concentrate human attention, don't scatter it (3.4's routing): put people ONLY where they add irreplaceable value (judgment, consequential decisions, edge cases) and NOWHERE else — so a human reviews the flagged 5%, not all 100%. This is what makes agents leverage-positive: they handle the volume; humans handle the judgment. Monitoring is a reliability layer (5.5's run-logs, agent edition): you can't watch every run, so the agent must be OBSERVABLE — logging its actions, decisions, costs, and failures — so you can audit, catch drift, and improve. An unobservable agent is an untrustworthy one.

Recap

Reliability engineering makes agents deployable: evals gate deployment on realistic and adversarial input, deterministic guardrails enforce hard limits, human-in-the-loop concentrates people at high-consequence/low-reversibility/low-confidence points, and observability makes the whole thing auditable — autonomy without reliability is just automated risk.
