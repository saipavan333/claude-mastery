4.3 · Memory: What Claude Remembers

Claude can now remember you between chats. That's genuinely useful and worth understanding precisely — what's kept, where it lives, and which dials are yours.

In one breath: Memory lets Claude carry facts and preferences across conversations — separate from Projects' curated context — with user controls to view, edit, disable, or go incognito; operators treat it as a convenience layer, never the system of record.

The three layers people confuse

Layer Lifespan You met it in Context window One conversation — the desk, wiped between chats 1.2 Project knowledge + instructions Curated by YOU, per room, until you change it 4.2 Memory Accumulated by CLAUDE across chats — preferences, recurring facts, ongoing projects this lesson The critical distinction: Projects are deliberate context (you chose every file); memory is gathered context (noticed along the way). Both useful; different trust levels. As of July 2026, memory can also be scoped per-Project on paid plans — client A's remembered details staying inside client A's room is exactly the leak-prevention you'd hope for (4.2's rooms extend to remembered facts).

The dials you own

See it: Settings exposes what Claude has remembered — as editable summaries. Read yours; it's an odd and useful mirror. Edit/delete: remove single memories or wipe all. Wrong remembered facts are worse than none (a stale «user prefers formal tone» quietly mis-steers every chat — 4.2's stale-shelf problem, auto-generated). Steer it in-chat: «Remember that I…» and «Forget what I said about…» work as first-class commands. Memory takes dictation. Go incognito: chats that don't read or write memory — for sensitive topics, one-off weirdness, or testing how Claude behaves un-briefed (useful for your 3.6 evals: memory OFF for reproducibility). Kill switch: disable memory entirely and live on context + Projects alone — a legitimate professional configuration, not paranoia.

The operator's memory policy

Convenience layer, not system of record. Anything that MUST be right (client facts, prices, policies) lives in Project knowledge where you version it — memory is for greases-the-wheels preferences («metric units», «I'm in Hyderabad», «bullet-point summaries»). Deliberate deposits: end useful sessions with «remember these two things: …» — curated memory beats ambient memory. Quarterly audit: skim the memory page, delete the stale, correct the wrong. Five minutes; prevents a drip of subtle mis-steering. Sensitive-by-default rule: health, finances, other people's private details — incognito unless you have a reason. Not because anything's wrong; because «minimum necessary» is what professional data-handling looks like, and YOU are now a professional (clients will one day ask you their version of this question — Track 11.7).

Recap

Three layers — desk (context), shelf (Projects), file (memory): keep must-be-right facts on the shelf, make deposits deliberate, audit quarterly, and use incognito like a professional uses discretion.
