9.3 · Vision & PDFs: Claude Reads Everything

Vision and documents on the API: sending images and PDFs so your products can read receipts, analyse charts, and process paperwork at scale.

In one breath: The API accepts images (via base64, URL, or the Files API) and PDFs (text + visual understanding, hundreds of pages), so the reading skills you used in chat (4.4) become programmable pipelines — with the same eyes-for-judgment, code-for-math discipline.

Sending images

Three ways to give Claude an image, same result: vision.py — an image in a message message = client.messages.create( model="claude-sonnet-5", max_tokens=500, messages=[{ "role": "user", "content": [ {"type": "image", "source": { # base64, url, or file_id "type": "base64", "media_type": "image/jpeg", "data": image_base64, }}, {"type": "text", "text": "Extract vendor, date, total, and line items as JSON. Unreadable fields = null, never guess."}, ], }], ) copy Content becomes a list when mixing images and text — images and instructions in one message. Multiple images per message are supported (comparisons, multi-page). Three sources: base64 (embed the bytes), URL (point to a hosted image), or Files API (upload once, reference by ID — best for reuse; below). It's real vision (4.4): charts, handwriting, diagrams, screenshots, damage photos. And the extraction contract (3.3) rides in the text part — «null never guess» is doing the same job it always did.

PDFs: documents at document scale

Native PDF support: send a PDF and Claude reads BOTH its text and its visual layout — tables, charts, form fields, scanned pages (it sees page images too). Hundreds of pages per request (the exact ceiling scales with model/context — 1M-context models go furthest; verify current limits in docs). This is the 3.2 long-context skill, applied to real documents: the quotes-first grounding, the ABSENT-not-invented rule, the docs-top-task-bottom layout — all transfer. A 200-page contract analysis in chat is a 200-page contract analysis in a pipeline. The killer pattern: structured extraction from document floods — invoices, claims, contracts, forms, statements → clean data, at volume, with the totality and null-honesty contracts (3.3) enforcing trustworthiness. This is a HUGE slice of the real-world money in AI, because every business drowns in documents (6.2's spreadsheet-epidemic point, generalised to all paperwork).

The Files API and the vision discipline

Files API: upload a file once, get an ID, reference it across many calls — instead of re-sending a big PDF's bytes every time. Saves bandwidth and, with caching (9.6), money. The right way to handle documents you'll query repeatedly. The discipline is 4.4's, non-negotiable at scale: eyes for reading/judgment, CODE for the math. If your pipeline needs «sum of all invoice totals», Claude extracts each total (vision) and your CODE sums them (arithmetic) — never ask the model to total 40,000 numbers in its head (4.4's professor/calculator law, at industrial scale). Verification scales by form (5.3): you can't eyeball 40,000 extractions — so build reconciliation (totals that should match a control figure), sampling (spot-check N random extractions against sources), and confidence/UNREADABLE flags routing the doubtful to humans. The 3.4 truth stack, in production. Cost awareness: images and PDFs consume tokens (vision has real token cost; big PDFs are big) — model choice matters (Haiku for simple extraction volume, Sonnet/flagship for nuanced documents — 1.3), and 9.6/9.7's economics become load-bearing.

Recap

Vision and PDFs make chat's reading skills programmable at scale — same extraction contracts, same eyes-for-judgment/code-for-math law, plus reconciliation and sampling to make bulk extraction trustworthy; the document-to-data pipeline is a huge slice of real AI money.
