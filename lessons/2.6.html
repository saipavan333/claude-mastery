2.6 · System Prompts & Roles: Casting the Actor

System prompts and roles: the stage directions that shape every line Claude speaks — and where to set them in each surface.

In one breath: A system prompt is standing instruction that frames the whole conversation — who Claude is, what rules bind it, what good output looks like — set via role lines in chat, custom instructions in Projects, CLAUDE.md in Claude Code, or the system parameter on the API.

What a role actually does

Saying «You are a senior pediatric nurse» doesn't unlock hidden medical files — it conditions the prediction (1.1) toward the vocabulary, caution, priorities and framing that co-occur with that voice in training. Effects you can bank on: Register: a CFO-role answer leads with numbers; a kindergarten-teacher-role answer leads with warmth. Same facts, different physics of emphasis. Priorities: «security-first code reviewer» genuinely surfaces different issues than «performance-first reviewer» on the same code — role selects what gets noticed. Calibration: «cautious analyst who flags uncertainty» hedges more honestly than default. Roles can implement 1.6's discipline. Good roles specify expertise + audience + disposition : «You are an experienced startup CFO advising a first-time founder; direct, numbers-first, allergic to vanity metrics.» Weak roles are empty status: «You are the world's best marketer» adds confidence, not competence — a nuance the frontier keeps confirming: describe the behaviour you want, not the trophy shelf.

System prompts: the standing version

A role you'd retype every chat wants to become a system prompt — instruction that applies to the whole conversation, sitting «above» your messages. What belongs there: identity and voice, standing rules («cite sources for factual claims», «UK English», «never invent data — say so»), output conventions, and context that never changes (your company, your audience). What doesn't: today's task — that's the message's job. Keep the contract stable, pass the work per-request. The four homes (each explored later in its own track): Surface Where the system prompt lives Any chat First message convention: open with the role/rules block, then the task (works everywhere, zero setup) Claude app — Projects Custom instructions per Project: standing direction for everything inside (4.2) Claude Code CLAUDE.md — a file of standing project rules the agent reads every session (7.3) API The literal system parameter — where your product's soul lives (9.2) Notice what this table really says: the skill you're practising in chat IS the skill of product-building. A Project's custom instructions, a CLAUDE.md, and a product's system prompt are the same craft at three altitudes.

Multiple perspectives: casting as a thinking tool

Because roles select perspectives, deliberately switching them is an analysis technique: The panel: «Answer three times: as a growth marketer, as a CFO, as a burned-out customer. Then reconcile.» Three lenses, one prompt, disagreements exposed. The red team: «Now be the harshest competent critic of the plan above» — the fresh-eyes discipline of 1.6, castable on demand. The audience stand-in: «React to this pitch as a skeptical procurement head with a frozen budget» — rehearse against the person you'll actually face.

Recap

Cast deliberately — expertise, audience, disposition, rules — put durable direction in a standing system prompt (chat opener → Project instructions → CLAUDE.md → API system param), and use role-switching as an analysis tool.
