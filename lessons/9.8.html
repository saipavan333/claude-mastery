9.8 · Ship It: A Real Mini-Product, End to End

Ship it: build a complete mini-product end to end — idea to running, reliable, cost-aware thing — proving you can do the whole loop, and creating a portfolio piece that argues for you.

In one breath: The track's synthesis: take one real idea through the full build — prompt design, API integration, tool use or vision, structured outputs, cost engineering, verification, and a usable interface — shipping a small but complete product that demonstrates every skill at once.

What «complete» means (the shipping checklist)

A mini-product isn't a script — it's a small system with every layer present. Your build must have: A real job: it solves an actual problem for a real user (even if that user is you). «A tool that turns my meeting recordings into action-item emails» beats «a demo of the API». Sound prompt engineering (Tracks 2–3): system prompt as the product's soul (2.6), format contracts (2.4), truth rules (3.4) — the intelligence layer, done right. The right API features (this track): tool use if it acts, vision if it reads documents, structured outputs for anything your code parses, streaming if a human watches. Reliability (3.4, 9.5): verification where it matters, honest failure (never fabricate), errors handled — it works on the messy real input, not just the happy path. Cost-awareness (9.6–9.7): right model(s), caching if there's a stable prefix, a spending guardrail — it's economically sane. An interface: something a human uses — a simple web page (an artifact! 4.5, or a small HTML front-end Claude Code builds), a CLI, a form. The AI is the engine; the interface is the product. Shippability (7.8): README, secrets clean, in a repo — a stranger could run it. This is the portfolio-piece standard.

The build loop (7.8, applied to a product)

PLAN: pick the idea (small enough to finish, real enough to matter), name its user and its one job, sketch the architecture (what models, what tools/vision, what the interface is), and — critically — the verification plan and cost model (9.7) BEFORE building. BUILD with Claude Code (Track 7): scaffold, integrate the API, build the interface, in reviewed small steps on a branch. The agent writes the code; you direct and verify — the whole builder phase, applied. VERIFY: run it on real, messy input including edge cases; confirm the verification and honest-failure behaviour; check the cost is sane; make sure it works for someone who isn't you. SHIP: README, secrets audit, commit, push. Optionally deploy (a static front-end + the API can go live cheaply). Then USE it for real — the ultimate test.

Why this matters more than it seems

Integration is the real skill. Knowing each feature separately is necessary; assembling them into a working whole is the actual job — and the thing employers and clients actually test for (13.5's interviews are «show me something you built»). The portfolio argument (7.8, 13.3): a repo of small, real, working AI products is 2026's most credible resume — undeniable proof, not claimed skills. This build is its first serious entry. The product could be a business (Track 12): many real micro-SaaS started exactly here — a mini-product that solved the builder's own problem, then others'. Your capstone might be your first income (12.1 will ask you to look at it that way). Confidence made real: after shipping one complete thing, «can I build AI products?» stops being a question. That certainty — earned, not claimed — is what carries you into the money tracks.

Recap

Ship one complete mini-product — real job, sound prompts, the right API features, reliability, cost-awareness, an interface, stranger-runnable — integrating the whole course into undeniable proof you can build; it's your portfolio's first entry and possibly your first business.
