8.2 · Using MCP Servers & Connectors Safely

Operating the plumbing: adding servers to Claude Code and the app, scoping their powers, and the trust checklist that runs before anything gets connected.

In one breath: Adding MCP servers is one command or a few clicks — the craft is what runs BEFORE (source trust, permission review) and AFTER (least-privilege config, calibration testing) — because a server is code with reach, installed into your AI's hands.

The mechanics (genuinely easy)

Claude Code: claude mcp add [name] … registers a server — local (a command to launch: stdio) or remote (a URL: HTTP). Scopes control WHERE it's available: this project only, or everywhere you work. Project-scoped configs (.mcp.json in the repo) travel with the codebase — the team's plumbing, versioned (7.3's philosophy again). The app: the connector directory (4.7) is guided MCP — browse, authenticate (usually OAuth for remote services), grant, done. Desktop also supports local servers — your OWN machine's tools plugged into chat. Everywhere: after adding, the tools simply appear in the model's repertoire — chosen by description (8.1) when relevant. Removal is equally simple; connections are decisions, not marriages.

The pre-connection trust checklist

Run it BEFORE adding, every time — sixty seconds: 1. Who wrote it? Official servers (from the tool's own vendor or Anthropic's catalogue) > well-maintained community servers with visible source and users > random repos. Servers run CODE with CREDENTIALS — provenance is everything (4.8's skill-trust rule, with higher stakes). 2. What can it touch? Read the tool list before installing (the source or docs tell you). A «calendar» server exposing delete_all_events deserves a pause. Match offered powers to your actual need. 3. Read vs write vs destroy: the recurring ladder (4.7, 5.2). Prefer servers (or configs) that let you grant read-only where read-only serves. Destructive tools connected «just in case» are risk purchased for nothing. 4. Where do credentials live? Proper servers take keys via environment/config on YOUR side (7.8's secrets law) — never hard-coded, never sent to third parties beyond the tool itself. 5. Local or remote? Local stdio = code running on your machine (audit it like software). Remote = your data transiting someone's service (audit it like a vendor). Different questions; both have them (8.3 deepens the remote side).

After connecting: calibrate, then rely

The week-one protocol (4.7's, verbatim): read-only exploration first; verify a few results against ground truth; watch which tools the model actually picks (mis-picks reveal description problems — yours to work around or report). Configure the fences: Claude Code's permission system governs MCP tools like any action — sacred paths and dangerous tools can be hook-blocked (7.5); approval modes apply. A powerful server behind good fences beats a weak server behind none. Prune quarterly: the connector audit joins your 4.3/5.5 review rituals — unused servers are attack surface with zero yield. Connections are decisions; re-make them periodically.

Recap

Adding is easy; the craft is around it — checklist before (provenance, powers, privileges, secrets, transport), least-privilege enforced below the AI layer, calibration after, cards kept, quarterly prunes.
