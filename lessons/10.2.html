10.2 · Workflow Patterns: Chain, Route, Orchestrate

Anthropic's playbook for effective agents: the workflow patterns — chaining, routing, parallelisation, orchestration, evaluation — that give you autonomy's power with control's safety.

In one breath: Effective agentic systems are built from named patterns — prompt chaining, routing, parallelisation, orchestrator-workers, and evaluator-optimizer — each adding capability while keeping control; you compose them, reaching for full autonomy only when no pattern suffices.

The five workflow patterns (you already know four)

Pattern Shape You met it in Prompt chaining Fixed sequence: output of step 1 feeds step 2 feeds step 3, with checks between 3.1 — the refinery Routing Classify the input, send it to the right specialised handler 1.3's model mix, 9.7's difficulty-routing, 10.1's exception-routing Parallelisation Split work across simultaneous calls (sectioning) or run the same task multiple times and aggregate (voting) 3.1's map-reduce, 5.6's sub-agents, 3.4's multi-critic verification Orchestrator-workers A central model breaks a task into subtasks dynamically, delegates to workers, synthesises 5.6's operation, Research mode's dig-and-synthesise (4.6) Evaluator-optimizer One model produces, another evaluates against criteria, the producer revises — loop until it passes 3.4's generator-critic, 3.6's eval loop, 7.8's verify beat Notice: these aren't new — they're the shapes you've been building since Track 3, now NAMED and recognised as the agent-building vocabulary. Fluency in them means you can describe and design agentic systems precisely.

Workflows vs agents (the key distinction)

Workflows = the patterns above: predefined paths, model makes decisions at SPECIFIC points, but the overall structure is FIXED and inspectable. Predictable, debuggable, cheaper. Cover the vast majority of «agentic» needs. Agents = the model dynamically directs its OWN process — choosing tools, sequencing steps, deciding when done — with the path emergent, not predefined. Maximal flexibility, maximal cost/unpredictability. For genuinely open-ended tasks only (10.1). The playbook rule: compose workflow patterns first; reach for a true dynamic agent ONLY when the task's shape can't be predefined. Most real systems are workflows with maybe one agentic component — exactly 10.1's invoice decomposition. Every pattern keeps a human-designable control point: chains have inspection between steps, routing has an auditable classifier, evaluator-optimizer has explicit criteria — the patterns are popular BECAUSE they preserve control while adding capability.

The three principles under all of it

Anthropic's guide distills to three principles that should govern every agentic build: 1. Simplicity: start with the simplest thing; add complexity only when it demonstrably improves outcomes (10.1's ladder, restated as law). 2. Transparency: make the agent's planning and steps VISIBLE — you (and users) should see what it's doing and why. Hidden reasoning is undebuggable and untrustworthy (Claude Code's diffs, Cowork's plans, Research's citations — all transparency in action). 3. Well-crafted tools (the ACI — 8.4): invest in the agent-computer interface as much as the prompts — clear tool descriptions, good schemas, teaching errors. Agents are only as good as the tools they wield, and tool design is where much agent quality actually lives. The synthesis: a great agentic system = the simplest composition of named patterns that solves the task + transparent operation + well-crafted tools + verification + security (8.5) + cost-awareness (9.7). Not magic — engineering, from a known playbook. That's the entire discipline, and it's learnable, which is exactly why it's valuable and why you can do it.

Recap

Effective agents are composed from named patterns — chaining, routing, parallelisation, orchestrator-workers, evaluator-optimizer — governed by simplicity, transparency, and well-crafted tools; workflows (predefined, inspectable) cover most needs, and dynamic agents are reserved for the genuinely unscriptable.
