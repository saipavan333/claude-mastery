5.3 · File Automation: Organize, Extract, Transform

The bread-and-butter of delegation: extract, transform, organise — folder-scale patterns that turn document chaos into structured, usable assets.

In one breath: Most valuable Cowork work is one of three patterns — extract (many files → one structured dataset), transform (every file → new format/shape), organise (chaos → system) — each specified with contracts, quarantines and receipts.

Pattern 1 — EXTRACT: many files, one dataset

Shape: a folder of documents (invoices, CVs, contracts, reports) → one structured output (spreadsheet, index, database-ready file). The spec is your 3.3 contract, folder-sized: schema by example, types, null-honesty («unreadable → null, never estimate»), totality («one row per source file, SKIPPED rows included; row count = file count»), and source-binding — every row carries its source filename , so any value is one click from its origin (3.2's quotes-first, filesystem edition). Scale changes verification, not principles: you can't eyeball 400 rows — so the spec includes machine-checkable receipts (count checks, totals that should reconcile) plus a random spot-check ritual (pick 5 rows, open their sources — 1.6 sampling). Classic jobs: invoices→expense sheet; CVs→candidate matrix; contracts→terms register; survey PDFs→response table; receipts→tax prep.

Pattern 2 — TRANSFORM: every file, new shape

Shape: N inputs → N outputs, each converted, reformatted, cleaned or re-voiced. The map discipline (3.1): one clear per-file rule, applied uniformly — «each meeting transcript → a one-page minutes doc using my minutes skill (4.8!)», «each product photo folder → renamed and web-resized copies», «each old proposal → the new template». Outputs beside, never over: transformed files land in Out/ mirroring the input structure; originals untouched. Reversibility by architecture (5.2), zero willpower required. Skills shine here: if the transformation is one you do often, the per-file rule should BE a skill — Cowork applies it ×200 with your edge-cases and truth rules riding along automatically. The 4.8 staircase, paying compound interest.

Pattern 3 — ORGANISE: chaos into system

Shape: an unstructured pile → a designed structure (you met it in 5.1's first delegation; here's the full craft). Design the taxonomy BEFORE the run — or better, make taxonomy-design step one: «propose a folder scheme for this mess based on what's actually in it; I'll approve before you move anything.» (Plan-checkpoint discipline, 5.2, applied to information architecture.) The three non-negotiables: move-don't-delete, Review/ quarantine for ambiguity, and the old→new receipt log. You know why by now — they're the same three every pattern needs, because they're the same three ANY trustworthy process needs: reversibility, honesty about uncertainty, auditability. Maintenance mode: once organised, the same spec re-run weekly keeps it organised — which is 5.5's scheduled tasks knocking on the door.

Recap

Extract with contracts and source-binding, transform to Out/ folders with uniform per-file rules, organise with pre-approved taxonomies — and verify at scale with receipts machines can check plus samples humans do.
