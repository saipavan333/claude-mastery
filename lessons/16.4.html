16.4 · Build-Along: Ship a Skill (Skills API)

Build-Along #A — package your expertise as an Agent Skill: a SKILL.md that Claude loads only when relevant (progressive disclosure), usable in the app, in Claude Code, and via the Skills API — and sellable as a product.

In one breath: An Agent Skill is a folder with a SKILL.md (a name, a when-to-use description, and instructions) plus optional scripts and references, which Claude loads progressively — metadata always, full instructions only when your request triggers it — so you can package a repeatable expertise once and have it apply automatically across the app, Claude Code, and the API, where custom Skills upload via the Skills API and run in the code-execution container.

Anatomy of a Skill (the SKILL.md)

A Skill is a folder. The one required file is SKILL.md , with YAML frontmatter and a body: SKILL.md — the shape --- name: invoice-extractor description: Extracts vendor, date, totals, and line items from invoice PDFs and images into strict JSON. Use whenever the user provides an invoice or receipt and wants structured data. --- # Invoice Extractor ## Instructions 1. Read every provided invoice/receipt. 2. Output STRICT JSON: {vendor, invoice_date, currency, subtotal, tax, total, line_items:[{description, qty, unit_price, amount}]}. 3. Any field you cannot read from the document = null. NEVER guess a number. 4. If totals don't reconcile (subtotal + tax != total), add a "flags" array noting the mismatch. ## Examples [one or two worked input->output pairs] copy The two frontmatter fields do the heavy lifting: name (lowercase, hyphens, ≤64 chars) and description (≤1024 chars) — and the description must say both what the Skill does and when to use it, because that sentence is how Claude decides to load it. Everything you learned about clear instructions (Track 2) and truth contracts (3.3–3.4) goes in the body. Optionally bundle more files — a REFERENCE.md, a schema, a Python script — and Claude reaches for them only if the task needs them.

Progressive disclosure: why Skills scale

The reason you can have many Skills without drowning the context window (1.2) is progressive disclosure — Skills load in levels: Level 1 — metadata (always): just the name + description, ~100 tokens per Skill. This is all Claude sees until something matches. Level 2 — instructions (when triggered): the SKILL.md body loads only when your request matches that «when to use» description — typically under a few thousand tokens. Level 3 — resources (as needed): bundled files and scripts are opened or executed only if the task calls for them; a script runs in the sandbox and only its output enters the context. This is the 1.2 desk-economics law turned into an architecture: expertise sits on the shelf costing almost nothing until the moment it's relevant, then loads just-in-time. It's why a Skill is a better home for a procedure than a giant system prompt — it pays rent only when it works.

Using and shipping Skills

In the app and Claude Code (4.8/7.5): drop the Skill in and Claude uses it automatically when relevant — the fastest way to test yours. Via the Skills API (GA, August 2026): Skills run inside the code-execution container , so you enable the code-execution tool, set the required beta header, and reference the Skill. Anthropic ships pre-built Skills you can call by id — pptx , xlsx , docx , pdf (document creation, ready-made) — and your custom Skills upload through the Skills API (the /v1/skills endpoints) and become available workspace-wide. Two constraints to design around: the container has no network access and no runtime package installs (pre-installed packages only), so a Skill is self-contained expertise, not a way to phone external services (that's what MCP and your own tools are for — Tracks 8–9). Exact request syntax is beta and evolving — author the SKILL.md with confidence, and verify the current API call shape in the Skills API guide before you wire it into a product.

Recap

An Agent Skill packages a repeatable expertise as a SKILL.md — a name, a precise 'what + when' description (the trigger), and proven instructions, plus optional bundled files. Progressive disclosure (metadata always, body when triggered, resources as needed) makes many Skills cheap to keep around — the 1.2 desk law as architecture. Skills work automatically in the app and Claude Code, and the GA Skills API lets custom Skills (uploaded via /v1/skills, run in the offline code-execution container) power agents you build and sell. It's the services-to-products leap in one file — capture a procedure once, deploy it everywhere.
