7.3 · CLAUDE.md & Steering: Teach It Your Project

CLAUDE.md and the steering stack: teach the agent your project once, in a file it reads every session — your constitution, promoted to infrastructure.

In one breath: CLAUDE.md is a markdown file in your project that Claude Code reads at every session start — project context, conventions, commands, rules — and it anchors a steering stack (rules, output styles) that makes every future session pre-briefed.

What goes in (and what stays out)

CLAUDE.md answers what a new collaborator would need on day one — because that's literally what the agent is, every session: Orientation: what this project IS, in three lines. The folder map: what lives where, which parts matter, which are legacy. Commands: how to run, test, and build this project — the exact incantations («run tests with: npm test», «rebuild data with: python build.py»). The agent uses these constantly; wrong or missing commands cost every session. Conventions: naming, formats, style — «dates ISO», «functions get docstring one-liners», «CSV outputs to /out, never /data». House law: your standing rules from 7.2's opener — plan-first, move-never-delete, receipts, the do-not-touch list. The constitution, filed. What stays OUT: today's task (sessions carry that), secrets and credentials (NEVER — files travel; 7.8 covers proper secret handling), and essays — the guidance is keep it lean (under ~200 lines): every line spends context every session (1.2's rent, paid at boot).

The living-document loop

Born from repetition: the second time you type the same instruction, it graduates to CLAUDE.md (the 2.7→4.2→5.6 promotion habit, now with a filename). The agent can even edit it for you: «add to CLAUDE.md: always regenerate the index after data changes.» Versioned like code: it lives in git, so its evolution is visible — and when Claude Code does something odd, «check what CLAUDE.md says about that» is a real diagnostic (the 4.3 layer-check habit: persistent instructions are a place bugs live). Scales with structure: big projects can carry nested CLAUDE.md files (a subfolder's file adds local law when working there) — global → local layering, exactly like 5.6's altitudes. And your personal, cross-project preferences can live in a user-level file (~/.claude/CLAUDE.md) — YOUR defaults, every project.

The rest of the steering stack

CLAUDE.md is the anchor; two siblings complete the stack (as of July 2026): Rules — path-scoped constraints loaded only when matching files are touched: «all files under /api: validate inputs with the standard checker». Sharper than CLAUDE.md for hard requirements because they fire exactly where relevant (and spend context only there). Think: folder-instructions (5.6) with a targeting system. Output styles — how the agent itself communicates: built-ins include an Explanatory mode and a Learning mode where it teaches as it works — a non-coder's best friend (the 7.1 free-education, made a setting). The mental model for the whole stack: CLAUDE.md = who we are here; Rules = hard law by territory; output style = how you talk to me; the session brief = today's work. Four layers, each at its widest-true scope — the 5.6 altitudes, fully industrialised.

Recap

CLAUDE.md briefs every session automatically — orientation, commands, conventions, law, under 200 lean lines, verified like load-bearing text, promoted-to on every second repetition — with Rules for path-scoped law and Learning mode for teach-as-you-go.
