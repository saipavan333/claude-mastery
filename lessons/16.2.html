16.2 · Projects, Rebuilt: Parallel Threads & Shared Memory

The redesigned Projects (September 2026): parallel threads that each run as their own cloud session, a shared memory every thread reads and writes, and a project library of everything produced. Built for work that spans days.

In one breath: The rebuilt Projects turns a project from a folder of chats into a multi-threaded workspace: each thread is its own Claude Code cloud session working on its own branch, every thread reads from and writes to one shared memory (so context stops getting re-explained), and a project library collects the files and artifacts produced along the way — purpose-built for long-running, multi-part work.

Parallel threads: many Claudes, one project

The headline change: each thread is its own Claude Code cloud session, working on its own branch. That means you can run several at once — one optimizing an API endpoint while another migrates a deprecated dependency while a third writes docs — instead of forcing serial work through a single chat. It is the 7.6 «parallel sessions» idea and the 10.2 orchestration pattern, promoted to a first-class feature of the workspace. For non-coders the same shape applies to non-code work: one thread drafting, one researching, one reconciling numbers — concurrently, under one project roof.

Shared memory: stop re-explaining

Parallelism only helps if the threads aren't strangers to each other. So every thread now adds to and draws from one shared project memory — the release-schedule change you mentioned Monday, the architectural decision made in another thread, the client contact, the naming convention — without you re-pasting it into each new conversation. This is the course's oldest theme (kill the re-briefing tax) applied at project scale: the project itself accumulates context, and each new thread starts already knowing it. It is 4.3's memory and 7.3's CLAUDE.md fused into a living, shared brief that the whole project reads and writes.

The library: the project remembers what it made

The third piece is a project library that collects the files and artifacts generated across the project's life, so it's easy to find what already exists and build new work on past efforts instead of redoing it. Combined, the three features change the unit of work from «a chat» to «a project that runs itself forward»: threads do the work in parallel, memory keeps them coherent, the library keeps the output. Availability (September 2026): the redesign launched in beta for select Claude Pro and Max users on cloud sessions, expanding to more Pro/Max users, with Team and Enterprise to follow — so exact access depends on your plan and the rollout; verify current status in your account.

Recap

The September 2026 Projects redesign rebuilds long-running work around three pillars: parallel threads (each its own cloud session on its own branch), a shared memory every thread reads and writes (so context accumulates and re-briefing stops), and a project library that collects what's produced so new work builds on old. It promotes 7.6's parallel sessions and 10.2's orchestration into the workspace itself — the unit of work becomes a project that carries itself forward, not a chat that forgets. Availability rolled out to Pro/Max cloud sessions first; verify your plan.
