10.3 · The Agent SDK: Claude Code as a Library

The Agent SDK: Claude Code's own engine as a library you deploy — build production agents with the harness Anthropic uses, on your own infrastructure.

In one breath: The Agent SDK (Python/TypeScript) packages the full Claude Code harness — the agent loop, built-in tools (read/write/edit/bash/search), subagents, hooks, sessions, permissions, MCP — as a library you host, so you build and deploy YOUR agents with battle-tested machinery instead of reinventing the loop.

What the SDK actually is

Claude Code, as a library: the Agent SDK (Python claude-agent-sdk , TypeScript @anthropic-ai/claude-agent-sdk ) is the harness that powers Claude Code (Track 7) — the agent loop, context management, sessions, subagents, hooks, permissions, MCP integration — extracted so you can build your OWN agents with it. Built-in tools included: unlike raw tool use (9.4, where you implement everything), the SDK ships with working tools — file operations (read/write/edit), bash, search (glob/grep), web search/fetch — so your agent can DO things immediately without you building the plumbing. You host and deploy it — on your servers, in your containers, your infrastructure. This is the key difference from Managed Agents (10.4, Anthropic-hosted): the Agent SDK is yours to run, giving total control (and total responsibility). Everything from Track 7 composes: point it at a project with CLAUDE.md, skills, slash commands and it uses them. The steering you learned for Claude Code applies to the agents you build with the SDK — same harness, same controls.

What you build with it

Custom coding agents: your own version of Claude Code, specialised for your codebase and workflows, embedded in your tools (a code-review bot, a migration agent, a docs-generator). Non-coding agents too: the harness's file/bash/search tools power any file-and-command-heavy agent — data pipelines, ops automation, document processing (Track 7.7's territory, now programmable and deployable). Embedded in products: the SDK is how you put an agentic capability INSIDE your software — a research agent in your app, an automation agent in your platform, deployed for your users. The pattern-composition (10.2) is yours to implement: subagents for parallelisation, hooks for evaluation/guardrails, the loop for orchestration — the SDK gives you the primitives; you compose the patterns.

SDK vs raw API vs Tool Runner vs Managed Agents (the map)

The builder's options, clarified (as of July 2026): Option What it is Reach for it when… Raw Messages API + your own loop (9.4) You build everything: loop, tools, context Maximum control, simple needs, or learning — but you reinvent a lot Tool Runner SDK helper that runs the tool loop over tools YOU define (no built-in tools) You want the loop handled but your own custom tools only Agent SDK Full Claude Code harness + built-in tools, YOU host Building serious agents you deploy and control — the workhorse for custom agents Managed Agents (10.4) Anthropic-hosted agent runtime, no infra You want agents without running servers — next lesson The decision axis: how much do you want to BUILD vs how much do you want HANDLED, and do you want to HOST or not. The SDK is «harness handled, tools included, you host» — the sweet spot for most serious custom agents. And all of it composes with everything you've learned: the SDK-built agent still needs good prompts (2-3), verification (3.4), cost engineering (9.7), and security (8.5) — the SDK provides the harness, not the judgment.

Recap

The Agent SDK is Claude Code's proven harness as a self-hosted library — loop, built-in tools, subagents, hooks, permissions included — so you build serious custom agents on battle-tested machinery while providing the judgment (prompts, tools, verification, cost, security) that can't be libraried.
