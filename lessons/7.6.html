7.6 · Parallel Sessions & Background Work

Scale: parallel sessions in isolated worktrees, background processes that grind while you direct, scheduled runs, and cloud sessions that work while your laptop sleeps.

In one breath: Claude Code scales horizontally — parallel sessions each in their own git worktree, background tasks for servers and long jobs, scheduled tasks for recurring runs, and web/cloud sessions on Anthropic's infrastructure — turning one director into a department.

Parallel sessions and worktrees

The desktop's parallel design (2026): the app runs multiple sessions side by side — different projects, or different tasks on the SAME project. For the latter, each session gets its own git worktree : a separate working copy of the repo, so two agents editing «the same project» never touch the same files mid-flight. Isolation by architecture (5.6's sub-agent slices, now for whole sessions). What parallelises well: independent tasks (feature A + docs cleanup + data run), explorations (two sessions trying two approaches to the same problem — pick the winner, discard the loser: checkpoint-thinking at session scale), and the classic: one session building while another reviews. What doesn't: two sessions editing the same tightly-coupled thing toward different goals — worktrees prevent file collisions, not INTENT collisions. Director's job: partition the work (the 5.6 split logic — no overlaps by construction).

Background and scheduled work

Background tasks: long-running processes — dev servers, big test suites, data crunches — run in the background while the session continues directing. The agent monitors output and reacts (test failures flow back into the loop). No more «wait for the run to finish» dead time. Scheduled tasks, terminal edition: recurring runs configured from the desktop app — the nightly data pull, the weekly dependency check, the Monday report build. Everything 5.5 taught (proven-first, read-and-draft defaults, honest failure, run-logs) applies VERBATIM — the discipline transferred; only the venue changed. Claude Code on the web: sessions running wholly on Anthropic's cloud — kick off from a browser, close the laptop, return to a completed branch and a proposed pull request. Sandboxed by design (7.4's full-auto habitat). The Cowork remote-session idea (5.1), for repositories.

The director's discipline

Partition before parallelising: name each lane's outcome and files-territory first («session A: /reports only; session B: /ingest only»). Collisions are prevented at the SPEC, not discovered at the merge. One review rhythm: parallel work multiplies diffs — batch your reviews (each session's work reviewed at ITS checkpoints) rather than thrashing between lanes mid-thought. Directors context-switch on purpose, not on interrupt. Receipts per lane, merge with checks: each session ends in its own commit with its own receipts; merges get the seam-check (5.6's law — parallel work's bugs live at the seams). Know your own limit: two to three active lanes is a strong human's real capacity for QUALITY review. More lanes than review capacity = rubber-stamping wearing a productivity costume (7.2's cardinal sin, at scale).

Recap

Partition, then parallelise: lanes with disjoint territories in worktrees, long jobs in the background, proven work on schedules and cloud night shifts — and never more lanes than your honest review bandwidth.
